# Project notes (Cybond)

- Workspace standards live in `~/code/CLAUDE.md` — pnpm only, TDD, 100% statements/functions/lines coverage (branches ≥97%), Conventional Commits, rebase-only git.
- **`WeekCalendarView` never resyncs from props.** It seeds internal state once and applies move/resize/delete/drag-create optimistically. `CalendarClient` restores server truth by remounting via `key={weekStart-resetKey}`; after create, a dedicated `useTransition` + `resyncQueuedRef` delays the `resetKey` bump until `router.refresh()` completes (bumping synchronously remounts with stale props). Do not "simplify" this machinery.
- **Type taxonomy is `task` + `goal` (Wave 2.1).** The `habit` type was removed — habits are recurring tasks (`recurrence` column). `createTaskSchema` rejects `type:'habit'`. The `createHabit` server action still exists as a live AI-chat tool (inserts `type:'task'` + `recurrence:'daily'`) — do not delete it; the library `ActionConfirmCard`/`ChatPanel` entityType union still emits `'habit'` and the chat renderer path must keep handling it.
- **The app owns `ActivityFormDialog`** (`src/components/activity/activity-form-dialog.tsx`) — the single create/edit dialog for Activities and the calendar (edit passes `lockType`). The per-type `TaskFormDialog`/`GoalFormDialog`/`HabitFormDialog` were **deleted in Wave 2.1** along with the quick-add bar. Goal `targetDate` is emitted date-only and converted to noon-UTC ISO (`T12:00:00.000Z`) before `createTaskSchema` on BOTH create and edit paths (the `.datetime()` schema rejects date-only; this avoids the goal-date-wipe trap).
- **Calendar drag-create uses the library's inline popover** (`WeekCalendarView.onEventCreate` → app `handleEventCreate` → `createTask`), not a dialog. The popover emits `recurrenceFrequency: daily|weekly|monthly|yearly`; app fan-out only expands daily/weekly/monthly (`yearly` persists but never fans out — known gap).
- **Calendar wake→sleep window semantics (library override trap):** when `sleepEnabled=true`, `WeekCalendarView` forces a full 24h grid (`hourStart`/`hourCount` are IGNORED) and renders shaded sleep zones where drag-create is blocked. Windowed view therefore needs `sleepEnabled=false` + `hourStart`/`hourCount`; full-day view needs `sleepEnabled=true`. Wiring it inverted ships a dead window that mocked unit tests cannot catch (caught at the Wave 2.1 Preview Gate).
- **`TaskTimeFields` + `buildIso`/`toTimeSlot` live in `@crawfordyoung/ui` (≥0.13.1), not in the app.** `ActivityFormDialog` consumes them; don't reintroduce a local copy. UTC semantics are load-bearing — local `HH:MM` is a timezone bug that UTC CI will mask.
- **Goals/Tasks are unified into one `/activities` destination** backed by the single polymorphic `tasks` table (no per-type table). The `/goals`, `/habits`, `/tasks` routes were removed (Wave 2); the auth proxy redirects every unauthenticated path to `/login`, so a removed route is indistinguishable from a protected one in the unauthenticated e2e suite (a 404 is unobservable there — assert the `/login` redirect instead). Activities has search (`?q=`, debounced buffered input + `router.replace`), type/status filters, and a recurring toggle.
- **Wake/sleep hours persist to `calendarPrefs.workingHoursStart/End`** via `setCalendarWindow` (Settings → Calendar section, defaults 9/17 when no row). `getCalendarPrefs` returns `null` for no row — callers must default.
- **Dialog mocks in tests must surface data props** (render the values), not just component identity — identity-only mocks have hidden real contract bugs. And prop-value assertions against a mocked library component cannot catch the library overriding those props internally (the sleepEnabled trap above) — behavior that depends on library semantics needs the Preview Gate.
- **Two test trees, both run by vitest** (no `include` glob; only e2e excluded): co-located `src/**/*.test.tsx` AND `tests/unit/**`. Any component deletion/rename must clean both trees.
- Chat panel opens via `open-chat` CustomEvent; optional `detail.prefill` seeds the input. Listener must stay null-safe (`detail?.prefill`) — older dispatchers send no detail.
- E2E suite is deliberately unauthenticated (dummy `DATABASE_URL`, never touches the DB). Auth.js uses database sessions — authenticated e2e requires seeded postgres + forged session cookie and is its own planned wave.
- Vitest auth-mock gotcha: `vi.mocked(auth).mockResolvedValueOnce(null as never)` — plain `null` fails type-check.
- **AI gating is token-balance-only.** `plan` is display-only (highlights the current tier on `/tokens`); no plan-based feature gates remain. Unauthenticated or zero-balance users see the app fully — only Cy chat and AI reflections require tokens.
- **`token-balance-changed` CustomEvent contract.** Dispatched on `window` after any token spend (chat `onFinish` callback). `TokenChipLive` in the app layout listens and refetches the balance via `getTokenBalanceAction`. Any new token-spending feature **must** dispatch `new CustomEvent('token-balance-changed')` on `window` so the topbar stays in sync.
